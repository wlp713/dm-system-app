# DM 日常管理 App 原型 v0.4

这份说明对应当前代码原型，记录业务流程和演示边界。它用于评审现场操作逻辑，不代表已完成生产环境部署。

## 使用角色

- 执行人：首页只显示本人今日 4M 与上午、下午会议任务；可进入点检、异常待办和历史记录。
- 车间负责人：首页展示当前车间的样例完成率与执行人情况。
- 工厂管理员：首页展示全厂样例数据，并可调整演示会议时间。
- 设置页的角色切换只用于本机预览。实际部署时角色、姓名、车间和班次应由账号目录及服务端授权提供。

## 4M 点检

1. 按生产日期和目标班次进入一次 4M 提交，四类固定为人员、设备、物料、方法。
2. 每类必须选择“正常、异常、不适用”之一；空白不会被当作正常。
3. 本次提交共用一张现场照片，避免每类重复拍照。异常必须填写问题及生产影响。
4. 异常自动创建独立协同事项，并进入预设责任部门队列：人员→生产、设备→设备、物料→物流 / 仓库、方法→工程 / 工艺。优先级由执行人在异常项内选择，现场无需手填责任人。
5. 目前展示的是通用示例问题，不是各车间正式检查表。启用现场试运行前，管理员需按纸质标准表核实每个车间的项目和责任映射。

## 两小时检讨会议

- 这是每日生产检讨会议记录，不会按每两个小时自动生成点检任务。
- 每个车间每天记录上午、下午两场；管理员可在 10:00 / 10:30 和 14:00 / 15:00 中设置排程。场次不随白班、夜班重复生成。
- 已召开：填写实际时间、会议结论 / 后续动作，选择需要带入会议的未关闭异常，并上传照片。
- 未召开：填写原因、照片和重新检讨时间；系统创建一条发往生产责任队列的待办。

## 异常协同

异常与点检结果分开保存。处理状态依次为待接单、已接单、处理中、待复核、已关闭；跨班交接记为时间线事件，不会让问题从原队列消失。记录可通过手机系统分享面板转发到微信等工具；转发内容只是协同摘要，原始状态仍以应用记录为准。

## 数据与指标边界

- 当前版本使用设备本地存储。不同手机之间还不能共享记录，尚未接 Firebase、账号、真实推送和服务端时限。
- 首页排名是演示样例，不代表工厂实绩。正式指标分母必须来自工作日、班次、车间模板和任务排程；没有排程时应显示“无计划”，不能伪造 0% 或排名。
- 照片保存在本机。生产环境需要接入统一云端照片存储、上传重试和权限规则。

## 下一阶段上线条件

先由工厂确认车间 / 部门目录、正式 4M 表、责任部门映射、会议时间和计划分母；再配置用户角色范围及 Firebase 数据、安全规则与照片存储。若要为 iPhone 和 Android 提供可靠的跨设备通知，需在账号体系和后端事件基础上接入 APNs / FCM，并处理 iOS 签名分发。
